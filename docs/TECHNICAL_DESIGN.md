# 기술 설계: 입력·프레임·충돌·타격

## 업데이트 루프
고정 60Hz 게임 로직. 실시간 렌더링은 requestAnimationFrame. 잠금/일시정지/브라우저 포커스 이탈 시 입력 잔여 상태를 정리한다.

## 공격 3단계
Startup(선딜) → Active(유효) → Recovery(후딜). 기술별 타격·가드·캔슬·밸런스 손실을 데이터화한다. **프레임은 수치뿐 아니라 애니메이션 프레임과 충돌 박스가 일치해야 한다.**

### V5.1 코드 기준 기본값 (60fps)
| 공격 | Startup | Active | Recovery | 총 | 데미지 | 거리(px) |
|---|---:|---:|---:|---:|---:|---|
| 잽 | 4F | 3F | 7F | 14F | 7 | 67–241 |
| 훅 | 7F | 4F | 13F | 24F | 12 | 35–186 |
| 어퍼컷 | 10F | 4F | 16F | 30F | 16 | 16–139 |

강타는 Startup +5F, Active +1F, Recovery +8F를 기본으로 하며, AI는 별도 +2F Startup을 사용. 위 값은 **프로토타입 코드 초기치**이고 기획서의 예시 표와 동일한 최종 사양을 의미하지 않는다.

## 입력 버퍼
- 마지막 입력을 9F 유지하고, 실행 불가능할 때 저장
- Recovery 진입 후 적중을 확인한 다른 펀치로 캔슬 가능
- 캔슬 시작 시 이전 기술의 hitTargets와 판정 수명을 정리
- 가드 입력은 공격·경직·기상 상태에 따라 제한
- 웹 브라우저 포커스 처리, 한글 IME와 독립적인 KeyboardEvent.code 지원

## 충돌 박스
- Pushbox: 선수끼리 지나가지 못하도록 위치 보정
- Hurtbox: HEAD / BODY / LEGS
- Hitbox: Active 때만 생성; attacker.owner 와 target.side 필터
- Hit list: 동일 공격 모션에 한 대상 1회 적중
- 가드 성공/피격/카운터/가드브레이크마다 상태 전이 규칙이 우선
- 다운 선수의 Hurtbox는 판정에 참여하지 않음

## 타격 결과와 넉백
V5.1에서 각 공격에 기본 거리 이동, 후속 velocity(속도) 부여:
- 잽: `knock=8`, 기본 이동 가중치 ×1.2, 속도 기본 2.9
- 훅: `knock=17`, 이동 ×1.45, 속도 기본 4.7
- 어퍼컷: `knock=24`, 이동 ×1.7, 속도 기본 5.8
- 강타 ×1.3(거리) / ×1.25(속도), 카운터 ×1.22 / ×1.18
- 화면 좌우 경계 clamp로 이탈 제한

모델링 권고: 이동량을 프레임 단위 force로 분리하고 잔여 감쇠·마찰·로프 반사·모서리 충돌·히트스톱 중 누적 무효화 여부를 테스트. **기존 구현의 즉시 위치 이동과 후속 속도 이동 혼합은 QA 대상.**

## 그로기 / 다운 / 기상
- balance 붕괴 시 조건별 dizzy 또는 down
- dizzy: 조작 감소/공격 제한/전용 스프라이트
- down: 공격 불가, 타격 제외, 쓰러짐→바닥 유지→기상 프레임 시퀀스
- KO: 체력 0 후 플래시 타이머/피격 히스토리 정리; 최종 자세는 스프라이트로 표시, 회전 임시 처리 금지

## 성능 및 디버그
- B키로 Hit(빨강), Hurt(초록), Push(파랑) 박스 표시
- 파티클은 상한 제한, 한 프레임당 신규 객체 최소화
- 이미지/사운드 에셋은 런타임 반복 디코딩 없이 재사용
- 모바일 16:9 터치 영역과 FPS 안정화 테스트 필요
- 테스트 훅 `window.__boxingTest`는 개발용: 제품 배포 단계에서 비활성화 검토

## QA 체크리스트
- 공격 중 입력 버퍼가 1회만 발동하는가
- Active 전후에는 공격 판정이 없는가
- 후딜레이와 회수 스프라이트가 일치하는가
- 피격 직후 이동 속도는 크기·방향과 일치하는가
- KO 시 흰색 플래시가 잔류하지 않는가
- 다운 상태에서 가드/피격/공격이 중복 발생하지 않는가
- 기상 전환에서 발이 공중에 뜨거나 캐릭터 크기가 튀지 않는가
